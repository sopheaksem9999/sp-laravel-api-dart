# Changelog

## Unreleased

- `debug` option that sends `X-Debug` (D3): `SpApi(debug: true)` adds `X-Debug: 1` to every request and `SpDebug.on()` / `SpDebug.merge(options)` do it for one request (every `TableGateway` method and `rpc`), asking the SERVER for lazy-loading diagnostics and error debug details. It logs nothing on the client (see `SpLog`). The header is added after the auth and tenant headers and before per-request headers, so an explicit per-request `X-Debug` (even `0`) wins. The default sends no header. New file: `lib/src/debug.dart`.
- Optional redacted request logging (D1): `SpApi(logger: SpLogger(sink: ...))` delivers one `SpLogEntry` per HTTP attempt (method, redacted URL, status, duration, request id, attempt, `code`, `errorCode`). Modes `SpLogMode.perRequest` (default, only requests marked with `options: SpLog.on(headers:, bodies:)`), `all` and `off`. Headers and bodies are included only when asked for; redaction (sensitive header names, body and query keys at any depth, credentials in the URL, 2048-unit truncation, `<N bytes>`, `<multipart>`, `<stream>`) is built in and cannot be disabled, and request ids are sanitised. The redaction rules are shared with `@sokpheak/sp-laravel-api` through the same fixture: sensitive keys include `pin`, `pwd`, `pass`, `sig`, `authorization`, `cookie` and keys ending in `tokens`, `secrets`, `passwd`, `privatekey`, `signature`, `credential`, `otp`, `otp_code`, `recovery_codes` and similar (`error_code`, `country_code`, `idempotency_key` stay visible); header names containing `signature`, `pass`, `otp`, `jwt` or `bearer` are redacted; the URLs in `Link` and `Refresh` headers, `key=value` pairs in URL fragments and filter groups (`or=(...)`, `and=(...)`) naming a sensitive column are redacted. The sink runs inline; a sink that throws or returns a failing `Future` never changes the request result. Nothing changes for callers that do not set `logger`. New files: `lib/src/logging.dart`; shared fixture `test/vectors/log_redaction.json`.
- Fix (realtime recovery): a rejoin whose confirmation arrives late, during the retry backoff, stops instead of sending more subscribe frames and reporting a false `onSubscribeFailed`. On a final rejoin failure `onRecovered` now fires before `onSubscribeFailed`, and an exception thrown by `onSubscribeFailed` is caught, so it no longer surfaces as an uncaught error or keeps `onRecovered` from firing. Unsubscribing (or a timed-out `subscribe` abandoning) the last channel a recovery was waiting for now completes the recovery.
- Fix: a realtime socket that dies silently is now detected and replaced. After a pong timeout the client closes the socket and handles the loss itself: `onDisconnected` fires once and it reconnects. Before, `WebSocketTransport.close()` emitted no `onDone`, so `isConnected` stayed true and nothing reconnected. `onAppResumed` now reconnects at once while a ping is unanswered and, after a long pause, sends a ping at once (before, it called `connect()`, which returned at once on a connected client), so a socket that died in the background is replaced after `pongTimeout`. A new connection no longer reports `isHealthy == false` because of a ping sent on the previous one.
- **Behaviour change:** `SpRealtime.onAppResumed` and `onNetworkChanged` reconnect only a client in use: one started with `connect()` (or `subscribe()`) and not stopped with `disconnect()` since. Before, an online event connected a fresh client (for example at app start, before login, since `connectivity_plus` emits the current state when listened to), and a resume revived a client the app had disconnected and re-sent its old subscribe frames. After `dispose()` both do nothing instead of throwing `StateError`.
- Fix: a failed `SpRealtime.connect` no longer sticks. Before, every later `connect()` returned the same failed future without trying again. A failed attempt is now retried after `reconnectDelay`, doubling per consecutive failure up to 5 s, unless the client is offline, disconnected or disposed; a later `connect()`, resume or online event tries again at once. Reconnects started by `onAppResumed`, `onNetworkChanged` or the reconnect timer no longer raise uncaught errors. A `connect()` still waiting for the handshake now fails with `SpApiError` (`network`) when the socket closes first or when `disconnect()` or `dispose()` is called, instead of never completing. `onDisconnected` fires only for a connection that was established.
- `SpApi.getBytes` and `AttachmentsModule.viewBytes` now return `Uint8List` instead of `List<int>`. A `Uint8List` response is returned as the same instance (no copy); other lists are converted. `Uint8List` is a `List<int>`, so existing callers keep compiling. Code that overrides or mocks `getBytes` or `viewBytes` (for example a mocktail stub) must now return a `Uint8List`, not a `List<int>`.
- **Behaviour change:** `SpRealtime.subscribe` now completes only after the server confirms the channel with `pusher_internal:subscription_succeeded`, and can throw `SpApiError` with code `timeout` after `subscribeTimeout` (default 10 seconds). A timed-out or authorization-failed subscribe leaves no registered intent. A second subscribe to a confirmed channel sends no new frame; concurrent subscribers on a pending channel share one confirmation. A failed re-subscribe after a reconnect is retried up to `subscribeAttempts` (default 3) with exponential backoff from `subscribeBackoff` (default 300 ms, capped at 5 s) and then reported once through the new `onSubscribeFailed(channel, error)` callback. New optional `SpRealtime` constructor parameters: `subscribeTimeout`, `subscribeAttempts`, `subscribeBackoff`, `onSubscribeFailed`. Custom `RealtimeTransport` implementations and test fakes must deliver `pusher_internal:subscription_succeeded` for each `pusher:subscribe`, or `subscribe` times out. They also must not emit `onDone` for a connection they close with `close()`, not even later (cancel the stream subscription first, as `WebSocketTransport` does): `SpRealtime` handles that loss itself and may already be reconnecting, so a late `onDone` would tear down the new connection. Known limitation: the Pusher protocol has no correlation id, so a very late confirmation (more than `subscribeTimeout`) of an abandoned subscribe frame can complete a new `subscribe` to the same channel early.
- Docs: README install snippet now targets `^0.1.0`; new sections for `rpc`, `SpApiError`, the `success: false` envelope, pagination, the select rule, `upsert` availability, retries, per-request options, attachments, realtime recovery and pairing with `sp_jwt_auth`. Samples are compile-checked in `example/readme_samples.dart` and guarded by `test/readme_test.dart`. The missing-`select` error names `requireSelect: false`.
- `AttachmentsModule.upload` (multipart form POST to `sp_attachments/rpc/upload`, `bytes` or `filePath`, `visibility` default `private`), `link` / `unlink` for record attachments, and `viewBytes` (authenticated `GET rpc/{id}/view`). Signed-URL methods and URL builders are unchanged.
- `TableGateway.list` and `serializeQuery` accept `direction` (`next` or `prev`) and `cursorColumn`, sent as `direction=` and `cursor_column=`.
- **Behaviour change:** an empty `cursor` is now sent as `cursor=` (empty string) instead of being remapped to `0`; the backend treats both as the first page. `cursor: null` still sends no cursor.
- **Behaviour change:** `CursorPage.nextCursor` is now `meta['next_cursor']` whenever the backend provides it, regardless of item count (previously only on full pages). It is null when absent; offset mode still yields no cursor.
- `RecordEvent` now exposes `eventName` (the broadcast event name), `raw` (the full payload as broadcast) and `isRecord` (true only when the payload has a string `table` and a map `record`). Non-record events such as `courier_location.updated` are delivered to the `subscribe` handler with all fields in `raw`. A non-map `record` no longer yields surprises: it gives an empty `record` and `isRecord == false`.
- **Behaviour change:** added `RecordAction.unknown`. A payload with a missing or unrecognised `action` now maps to `unknown` instead of `created`. Exhaustive `switch` statements over `RecordAction` need a new case.
- `TableGateway.list/get/create/update/patch/remove/restore/upsert` accept optional `Options? options` and `CancelToken? cancelToken`, forwarded to `SpApi.request` (per-request headers win over tenant/auth headers). Existing calls are unchanged.
- `SpApi.rpc` accepts optional `query` (query parameters), `method` (override; default stays POST with a body, GET otherwise) and `options` (Dio `Options` merged into the request).
- **BREAKING (behaviour change):** `SpApi.request` now throws `SpApiError` (status stays the HTTP status, e.g. 200) when a response with status < 400 has a JSON map body with `success: false`. Error code 10002 on such a response is routed through `ApiAuth.handleUnauthorized()` and retried once, like a 401. Bytes responses and non-map bodies are unaffected. Opt out with `SpApi(treatSuccessFalseAsError: false)` to restore the 0.1.0 behaviour.
- `SpApiError.retryAfter` now also reads `errors.retry_after_seconds` (first element, int or numeric string; zero or negative ignored) as a last fallback after the `Retry-After` header and body `retry_after`. The value remains in `fieldErrors`.
- `SpApiError` now carries the transport `cause` and `stackTrace` (the originating `DioException`) for status 0 failures, plus `isTransport` / `isHttp` getters. `toString()` never prints the cause.

- `iterate()`, `fetchFirst()`, `fetchLast()` and `cursorPagination().firstPage()` now send `cursor=` (cursor mode) so the backend returns `next_cursor`; `fetchPrev` sends `direction=prev`; `fetchLast` keeps `prevCursor` null on a single short page. `list` with a `null` cursor is unchanged (offset mode).
- `CursorPage.nextCursor` / `hasMore`: the backend sends `next_cursor` on every non-empty page, so the real end of the data is an empty page; docs updated.
- **Behaviour change:** `SpApiError.isTransport` is now true only for `network` and `timeout` errors with `status == 0`; local errors (for example a missing `select`) also have status 0 but are not transport failures.
- A `200` `success: false` envelope now maps `error_code` to `SpApiError.code` (10002 unauthenticated, 10008 forbidden, 10009 notFound, 10004 validation, 10010 server; others unknown).
- Retried multipart uploads (after a 401, a 10002 envelope or a `RetryConfig` retry) now send a fresh `FormData` clone instead of failing with "already finalized".
- Release note: the release containing the breaking `treatSuccessFalseAsError` default should be versioned 0.2.0.

## 0.1.0 (2026-10-27)

- First stable release of `sp_laravel_api` for Dart and Flutter.
- Added configurable `RetryConfig` with exponential backoff, full jitter, and `Retry-After` header parsing for transient HTTP errors.
- Added remote OpenAPI schema resolution (`--url`, `--schema`, `--header`, `--token`, `--tenant`) to typegen CLI.
- Added `Sort.reversed()` and cursor pagination boundary helpers (`fetchFirst`, `fetchLast`, `fetchNext`, `fetchPrev`, `cursorPagination`) on `TableGateway`.

## 0.1.0-beta.2 (2026-10-27)

- Verified automated GitHub Actions OIDC publishing pipeline to pub.dev.
- Enhanced CI hygiene tooling with default fallback checks.

## 0.1.0-beta.1 (2026-10-27)

- Initial beta release of `sp_laravel_api` for Dart and Flutter.
- Typed `TableGateway` with cursor and offset pagination.
- Query builder serializing filters, relationships, and sorting.
- Multi-broadcaster realtime engine for Laravel Reverb, Pusher, Soketi, and Ably.
- Cross-platform support for VM, web, and Wasm.
